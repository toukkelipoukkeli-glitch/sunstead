# DECISION REPORT — Tangled / AT Protocol Hackathon

> Generated by a multi-agent research+ideation workflow (27 agents): digested the
> existing framework, researched the ATProto/Tangled primitives, the YC + code-agent
> landscape, reputation/identity systems, and playful firehose toys, then generated 20
> candidate ideas, clustered to 10 finalists, and adversarially stress-tested each
> against the swap-test. Companion to [tangled-evidence-radar/](tangled-evidence-radar/).

**Track:** Tangled main challenge (4-min pitch, 2-day build, seeded data OK).
**What the sponsor (Lewis) rewards:** agentic + write-side + firehose-live + playful,
leaning on AT Protocol primitives for **state and ephemerality** instead of reinventing them.

---

## 1. Primitives that matter — the mental model

The one idea everything hangs on: **ATProto splits "speech" from "reach."** Your *speech*
(data) is signed, user-owned, portable, and lives in *your* server. *Reach* (apps) just
index that public commons. Normal stacks fuse them — the app owns the DB and the UI, so
your data is hostage to the app. Here the database is a public, signed, portable commons
any app can read or write. Every lever below falls out of that split.

| Primitive | The non-obvious property it unlocks |
|---|---|
| **DID + handle** | Identity is **not app-scoped**. A person's Tangled DID *is* their Bluesky DID. Given one DID you read their entire cross-app history with **no API key** — the join is free and cryptographic. |
| **PDS** | The **app doesn't own the data store**. Writes land in the *user's* server. You run a stateless index over storage you don't control — state is free and survives your app dying. |
| **Repo / Records / Collections** | Records are **signed + self-certifying** (provenance built in). rkeys are **TIDs that sort chronologically** → a free append-only event log per user per type. |
| **Custom Lexicons** ⭐ | **Invent a new global data type.** The instant a user writes one record it's live on the firehose for the whole network — no registry, no migration, no permission. Schema + transport + storage + realtime distribution, free. *Highest ceiling.* |
| **AT URIs + strongRef/CID** | **One address space spans every app and server.** Pin a CID → "I approved *this exact* diff," a tamper-proof cross-repo join with no foreign keys. |
| **Firehose / Jetstream** ⭐ | **Push notifications for events you don't own, zero producer-side integration.** Filter `sh.tangled.*` and you're subscribed to every PR/issue/push/CI-run network-wide. Cursor = replay/backfill (seed-friendly). |
| **Labels / Labelers** ⭐ | A **universal, signed, opt-in metadata layer over content you don't own.** Any DID = a labeler emitting retractable (`neg`), expirable (`exp`), CID-pinned annotations on any record. **Consumers pick which labelers to trust at request time.** `neg`+`exp` *are* the ephemerality primitive. *Most overlooked.* |
| **OAuth** | **Auth target = write target = the user's identity.** You write records *into their repo under their DID* — the artifact is theirs and outlives your app. |

**Tangled-specific:** every **repo and CI runner (Spindle) gets its own DID**. **Vouches**
(in `graph`) are public, transitive-one-degree trust records, built explicitly against
LLM-spam; the flagged-but-**unbuilt** roadmap is **vouch decay + evidence trails** (a vouch
strongRef'd to the exact PR). You can mint your own `sh.tangled.x.*` (stars were *literally*
just a new lexicon entry).

> ### The swap-test (state once, apply to everything)
> **Swap AT Protocol for "GitHub API + Postgres." If the idea still works — or works better
> — it's dead.** A winner gets *strictly worse* on the swap: it must lose at least one of
> **portable cross-app identity, zero-setup global firehose, federated custom-lexicon data,
> portable/retractable trust, or user-owned (no-DB) state.** And a judge must be able to
> repeat the before/after in **20 seconds**.

## 2. Landscape

### Crowded / commodity — avoid
- **Generic "review every PR off the firehose" bot** — the single most saturated space in
  software: **CodeRabbit, Greptile, Graphite Diamond, Qodo/PR-Agent, Korbit, Ellipsis,
  Sourcegraph Amp, Cubic, Copilot, Bugbot.** Swap Jetstream for a webhook and you've *built
  CodeRabbit.* Fails the swap unless trust/identity is load-bearing.
- **Generic "issue → PR" co-dev agent** — Sweep, Devin, Cursor, Claude Code, OpenHands.
  Only interesting if the agent is itself an ATProto actor (own DID/reputation).
- **Codebase-graph-for-context** (Greptile, Sourcegraph own it) — reinventing infra.
- **Centralized dev-reputation score** (**OpenSauced**) — fails the swap the *opposite* way:
  dies without GitHub's API.

### Whitespace — protocol-native, under-explored
Agent-as-first-class-citizen (own DID, portable/burnable bot reputation); write-side trust
artifacts (evidence-bonded vouches, labeler verdicts); cross-app surfaces that render Tangled
cred *inside Bluesky*; ephemeral-state-as-primitive (presence/scores as records or `neg`/`exp`
labels, no DB); playful firehose toys (**Tangled has no shipped leaderboard or game yet**).

### Transferable lessons
1. **CodeRabbit / Greptile / Sourcegraph** — every incumbent's moat is a *private,
   non-portable DB*. **The wedge:** ATProto turns each private moat into a public, portable,
   federated commons. That sentence is your pitch weapon.
2. **Statusphere** (atproto's canonical 4-step demo) — no-DB presence is a *solved, copyable
   template*. The fastest, lowest-risk write-side ideas extend Statusphere.
3. **WhiteWind / Popsky / Skylight** — prove data authored in one app *renders under the same
   DID* in Bluesky. "Your code cred shows up in your social profile" is *demonstrated*.
4. **OpenSauced** — centralized reputation that dies without GitHub's API. Reputation must
   live in user PDSes and be portable, or it fails the swap the wrong direction.
5. **r/place & One-Million-Checkboxes** — viral shared-canvas genres on pure shared state.
   The firehose *is* the multiplayer backend; "move = signed record, board = firehose" is the
   cleanest "didn't reinvent infra" play — and the lane is empty on Tangled.

## 3. Ranked ideas (total of 6 sub-scores: originality / inspiring / primitiveLean / demoability / notAClone / buildable)

### 1. Trustfall — **26** *(strong)* · 4 / 4 / 5 / 4 / 5 / 4
**One-liner:** One maintainer retracts a vouch / denounces a sockpuppet, and you watch the
trust shockwave ripple across the whole network live, recomputing who every repo can suddenly
no longer rely on.
**Load-bearing primitives:** `graph` vouch/denounce (transitive-one-degree) · Firehose on
graph writes · `neg` labels (retraction as a first-class event) · DID join · strongRef/CID
evidence pin.
**Swap-test:** **Holds.** No portable cross-org vouch graph exists on GitHub; a denounce in
org A is invisible to org B, and there's no firehose to broadcast a retraction. Swap it → a
single-org ACL, not a network seismograph.
**Demo moment:** Replay a recorded cursor; a respected maintainer denounces an LLM-spam
sockpuppet; in ~3s seven transitively-trusting repos flash red and one stacked PR drops from
"trusted lane" → "needs human," with the severed vouch AT-URIs in a sidebar.
**Buildability:** Strong — seed ~15 DIDs as static record-shaped JSON, transitive graph +
force-directed canvas client-side, scripted firehose replayer. No backend DB.
**Biggest risk:** Reads as "a node-graph that flashes red" — the failure that killed the
rejected *AT Review Graph*. The *consuming* workflow is asserted, not built.
**Strengthen:** Make the consuming workflow the hero — build **one** concrete downstream
artifact that mechanically flips on the retraction (a stacked PR's lane label
trusted→needs-human via a real seeded `neg`-label write), shown before/after. Demote the graph
to ambient context.

### 2. Soft-Lock Beacon — **26** *(maybe)* · 4 / 3 / 5 / 4 / 5 / 5
**One-liner:** Mint a federated "I'm working on this issue" record so two strangers on two
different knots stop duplicating a fix in real time, with the claim expiring on its own.
**Primitives:** custom lexicon `sh.tangled.x.claim` · Firehose · strongRef+CID to the exact
issue · TID ordering (first-claim-wins, no lock table) · DID-as-author.
**Swap-test:** **Holds.** A GitHub soft-lock is per-repo, never crosses host/fork boundaries.
**Demo:** Split-screen two knots; Dev A claims issue #42; a beacon lights on Dev B with Maya's
DID + vouches and greys out the draft-PR button; fast-forward past the ttl and the claim
self-expires live.
**Risk:** Value is *rare* (two strangers colliding inside a TTL on a young network) and ttl is
convention — "lock" reads as "suggestion."
**Strengthen:** Reframe from rare "soft-lock" to an always-on **"live presence layer for
code"** (reviewing / drafting-fix / investigating) any client renders — valuable even with no
collision. Use `exp`-labels so expiry is protocol-backed, not etiquette.

### 3. Drive-By Patch — **25** *(maybe, read-side caveat)* · 3 / 3 / 5 / 4 / 5 / 5
**One-liner:** A stranger fixes your typo; before you merge you see their whole cross-app self
— social-graph overlap, who already vouched them, their other repos — resolved from one DID,
no signup.
**Primitives:** DID cross-app join · `app.bsky.graph.follow` + `sh.tangled.graph.follow` as one
graph · transitive vouch aggregation · strongRef to merged pulls · OAuth write.
**Swap-test:** Holds, but read-side. **Caveat:** closest to Evidence Radar's hover card; the
OAuth-write is bolted on and removable.
**Strengthen:** Make **social-follow-overlap the entire spine** ("3 people YOU follow already
follow this stranger" as a live set-intersection); add a write-side hook with teeth (merge
emits an evidence-bonded vouch strongRef'd to this exact pull).

### 4. Hatcheck — **25** *(maybe, read-side caveat)* · 3 / 3 / 5 / 4 / 5 / 5
**One-liner:** A PR page where you flip between trust "lenses" — each lens a labeler you opted
into — and the same diff is cleared, flagged, or quarantined depending on whose signed
verdicts you choose to believe.
**Primitives:** Labelers (signed, opt-in, `neg`/`exp`, CID-pinned) · consumer-side labeler
selection at request time · DID-as-labeler · strongRef/CID · custom verdict lexicon.
**Swap-test:** Holds — "swap your lens, change the verdict" is structurally impossible on
GitHub. **Caveat:** read-side, same corner as Evidence Radar; nothing write-side/firehose-live.
**Strengthen:** Make the trust swap **live and external** — a separate labeler DID emits a real
`neg`/`exp` *during* the pitch so the flag clears because an independent reviewer changed their
mind and it propagated to a repo neither owns.

### 5. Skeet-to-Ship — **24** *(maybe, demoability 2)* · 4 / 4 / 5 / 2 / 5 / 4
**One-liner:** Reply to a code change from inside Bluesky and your reply becomes a real Tangled
review record under your DID — the social thread *is* the PR thread.
**Primitives:** DID identity (Tangled = Bluesky) · custom review lexicon · strongRef/CID ·
Firehose auto-posts the thread · OAuth write.
**Swap-test:** **Strongest in the set** — needs an unforgeable Twitter↔GitHub identity bridge,
impossible without a token-in-bio hack + rotting mapping table.
**Risk:** The magic is invisible plumbing; the Bluesky composer isn't embeddable, so the
load-bearing gesture must be faked → reads as "two divs sharing local state."
**Strengthen:** Use a real PDS + the presenter's actual DID; reply via a genuine Bluesky API
call; put the review record's `author` next to their last real Bluesky post's `author` —
**one key signed both**. The climax becomes the cryptographic join.

### 6. Standup Records — **23** *(maybe)* · 3 / 3 / 4 / 4 / 4 / 5
**One-liner:** Your "what I'm working on" status is one DID-owned record — live commits in
Bluesky, social context in Tangled, no DB, expires on its own.
**Risk:** Records don't natively expire, only *labels* do — a hole the founding-eng judge will
catch. **Strengthen:** commit fully to **labels-with-`exp`**; you're "active" *because you just
pushed* (`.git.refUpdate` auto-asserts a self-expiring label). Best buildability in field.

### 7. Bystander — **23** *(strong)* · 4 / 4 / 4 / 4 / 4 / 3
**One-liner:** Three rival review agents, each its own DID and stance, post conflicting
verdicts as their *own* records; the maintainer trusts whichever agent's track record held up
— review as a portable, accountable debate.
**Primitives:** multiple agent DIDs with portable reputation · Firehose on `.repo.pull` · each
verdict a signed comment strongRef'd to the pull CID · vouch/denounce of agents cross-repo.
**Swap-test:** Holds — GitHub bots reproduce the *argument* but not portable, burnable,
cross-repo DID reputation + non-repudiable CID-pinned verdicts.
**Risk:** Tightest timebox; the emotional center (bots arguing) is swap-neutral.
**Strengthen:** Make "who was right" a **clickable two-record proof** (a prior CID-pinned
"SHIP" next to the `.git.refUpdate` where that bug merged), then **denounce that agent live**
and cut to a different repo re-weighting its next verdict. **Pre-gate: confirm `graph` allows
vouching a non-human DID.**

### 8. Second — **22** *(maybe, honesty caveat)* · 4 / 3 / 5 / 3 / 4 / 3
**One-liner:** A DID-bearing agent watches the firehose for green CI, independently re-runs the
pipeline on its own knot, and emits a portable, expirable "independently-reproduced" label on
the exact commit CID.
**Caveat:** "independently re-runs your pipeline" is infeasible in 2 days (stubbed), and
"CID-pinned = tamper-proof" oversells (GitHub status checks already key to a SHA).
**Strengthen:** Cut to the one atproto-only beat (toggle the `@second` labeler off → chip
vanishes from every PR at once); drop the tamper beat.

### 9. Intent-to-Review Pledges — **21** *(maybe)* · 3 / 3 / 4 / 4 / 4 / 3
**One-liner:** Reviewers mint a public, expiring "I'll review this by Friday" pledge bonded to
the exact PR — turning ghosting into a commitment market with portable kept-promise reputation
any app can read.
**Caveat:** mapping pledge → subsequent review-round by the same DID on the same CID is neither
cleanly fake-seedable nor cleanly real-buildable in 2 days; risks a commodity SLA tracker.
**Strengthen:** Open from a mock Bluesky profile where the "kept 9/10" badge already lives under
the same DID, then cut to the stuck PR. Trace exactly one kept/broken example fully.

### 10. Stargrab — **21** *(maybe, buildable 2)* · 3 / 3 / 4 / 4 / 5 / 2
**One-liner:** A network-wide, no-backend multiplayer game where minting a custom-lexicon claim
record lets anyone "capture" a repo tile on a shared map — the board *is* the firehose.
**Caveat:** Lowest buildability — the two rubric-winning mechanics (`exp`-label decay, star
defense) are the two most likely faked; the fallback (client-side TID decay) silently becomes a
CSS animation that **fails the swap**.
**Strengthen:** Make `exp`-label decay **real and central** (pre-stand-up one labeler DID, short
`exp`, rehearse the self-reset as the money beat). Cut star-defense. Rewrite to "no game server
**I own**."

## 4. Recommendation

### Headline bet: **Trustfall** (26, the only "strong" in the top tier)
The rare idea that is *firehose-live, write-side-adjacent, playful (a seismograph), and
serious-valuable at once*, centering the **most overlooked primitive** (`neg`/denounce — the
retractable side everyone ignores) plus the **transitive vouch graph**. Clean 20-second swap
line: *"a signed retraction in user-owned records re-routed trust for the whole network — no
admin, no central DB; on GitHub a denounce in org A is invisible to org B."* Scores 5 on both
top-weighted axes. Fix the one weakness (looks like a viz) by wiring **one** real seeded
`neg`-label write that flips a concrete PR lane label.

**Relation to Evidence Radar:** Trustfall is the **dynamic, write-side dual** of the incumbent.
Evidence Radar reads trust *statically* to rank a queue (and treats firehose-live as a *cut*);
Trustfall makes trust **a live event** — the product *is* the retraction and its blast radius.

### Backup: **Bystander** (23, also "strong")
Lower total + tightest timebox, but the **purest expression of the sponsor's stated
excitement** (agentic *and* write-side) and the sharpest weaponization of the anti-commodity
wedge: many bots whose accuracy is a *public, portable, burnable commons*, disagreement as a
feature. Pick over Trustfall only if confident the team can land the clickable
"who-was-right" two-record proof + cross-repo re-weighting on stage, and has **confirmed
`graph` permits vouching a non-human DID** (hard pre-build gate).

**Cut / caveat:** **Second** and **Pledges** carry honesty/feasibility caveats. **Drive-By
Patch** and **Hatcheck** are strong on the swap but sit in Evidence Radar's read-side corner;
ship only with the prescribed write-side/live changes. **Stargrab** is the most fun but least
buildable.

## 5. Open questions for the sponsor (Lewis)

1. **Can a non-human DID be vouched/denounced in `graph`?** Make-or-break for **Bystander** and
   central to **Trustfall**'s denounce mechanic.
2. **What carries `exp`/`neg` — labels only, or can records expire?** Decides whether **Standup
   Records**, **Stargrab**, **Soft-Lock Beacon** get genuine protocol-backed ephemerality or
   fake it.
3. **Real `sh.tangled.graph` vouch/denounce semantics — does transitive-one-degree propagation
   + retraction exist today, or is it roadmap?** **Trustfall**'s seismograph is partly seeded
   fiction if propagation is thinner than assumed.
4. **Is minting a `sh.tangled.x.*` lexicon + writing records to `tngl.sh` realistic in the
   timebox (OAuth write, labeler endpoint)?** Gates the "it's real" beat for every write-side
   idea.
5. **Are judges scoring the *mechanism* or the *demo polish*?** If invisible-but-correct
   plumbing counts, **Skeet-to-Ship** rises; if only the on-screen "ohhh" counts, Trustfall /
   Bystander pull further ahead.
